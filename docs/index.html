Matter support for Indigo

Both directions. Commission with the ecosystem you already own and control everything from Indigo — and publish the Indigo devices you choose back out as a Matter bridge of your own.

Four field notes, written to be read in order or dipped into. Start with the protocol if Matter is new to you; jump straight to the direction you care about if it isn’t. The plugin itself installs from the Indigo Plugin Store — the install guide picks up from there.

№ 1 · the primer

What is Matter

The protocol on its own terms — transports and Thread, border routers, commissioning, fabrics and multi-admin, and what “uncertified” actually means. No Indigo, no plugin mechanics.

 № 2 · Matter in

The controller

The share model: your ecosystem commissions the device, the plugin joins as a second admin over plain IP. What lands in Indigo, what has been validated on real hardware over Wi-Fi and Thread, and what to check when it doesn’t work.

 № 3 · Matter out

The bridge

Indigo devices published as one Matter bridge accessory — the opt-in allow-list, the roles you declare, pairing into an ecosystem, and an honest account of exactly what has and hasn’t been proven.

 № 4 · for the curious & plugin devs

The Proving Ground

How all of it is tested — the unit suites, the device zoo, a fifteen-device virtual Matter fleet, the bridge node’s own suite, and live validation on a production server.

 Setup guide

Install & Configure

Step by step after the Plugin Store: the Matter controller, the export bridge, backups, security, and every troubleshooting table — the reference to keep open while you set things up.
